Sistema de diseño para los productos internos

Una sola base de tokens, ocho temas y tres densidades para el ERP web, la app móvil general, la app de inspección de bodega y la app de Recursos Humanos. El contrato común son variables CSS; la capa ds-* funciona igual en plantillas de Django, Vue 3 o React.

Use los selectores de arriba para ver cualquier componente en cualquier combinación de tema y densidad. Esa es la herramienta para validar los temas.

1. Cargar

fonts/fonts.css (fuentes locales), themes.css, components.css y, si quiere teclado avanzado, ds.js.

2. Elegir tema y densidad

<html data-theme="signal-blue" data-density="compact">. Se puede cambiar en tiempo de ejecución.

3. Usar clases ds-*

ds-field, ds-input, ds-btn ds-btn--primary, ds-table… y nunca colores literales.

<link rel="stylesheet" href="{% static 'ds/fonts/fonts.css' %}">  <!-- fuentes locales, sin internet -->
<link rel="stylesheet" href="{% static 'ds/themes.css' %}">
<link rel="stylesheet" href="{% static 'ds/components.css' %}">
<script src="{% static 'ds/ds.js' %}" defer></script>  <!-- opcional -->

Principios

Tokens antes que valores

Un componente nunca escribe un color, una medida o una sombra literal. Si falta un token, se agrega al sistema; no se improvisa en el producto.

El estado nunca es solo color

Cada estado lleva ícono, texto o forma además del color. Así funciona con daltonismo, luz solar directa y pantallas baratas.

La IA siempre se anuncia

Lo que genera un modelo lleva borde punteado y el nombre del asistente con «(IA)». Nada irreversible ocurre sin confirmación humana.

HTML nativo primero

<dialog>, <details>, <select>, <input type="date">: accesibles sin JavaScript y fáciles de renderizar desde Django.

La densidad es un eje, no un tema

Cualquier tema funciona en cualquier densidad. La densidad cambia alturas, rellenos e interlineado; nunca colores.

WCAG 2.2 AA es el piso

Los contrastes se calculan por código y se verifican en vivo en este documento. Un tema que no pasa no se publica.

1. Arquitectura de tokens

Tres capas con responsabilidades separadas. Solo la capa semántica cambia entre temas, y solo la capa de componente cambia entre densidades.

Primitivos

Valores crudos, sin significado. Cada tema tiene su propia paleta: rampa de neutros teñida, color de marca y colores de estado ajustados.

color/signal-blue/neutral-700color/signal-blue/accentspace/16 · radius/md · duration/base--ds-p-signal-blue-accent

Semánticos

Lo único que consumen los componentes. Cada tema los redefine apuntando a sus primitivos.

surface/raisedtext/secondaryaction/primaryfeedback/danger-text--ds-action-primary

De componente

Solo donde aportan: medidas que dependen de la densidad.

control/height-mdtable/row-heighttarget/min--ds-control-height-md

Nomenclatura

  • En inglés, kebab-case, con / como separador jerárquico: feedback/warning-bg.
  • En CSS, el separador se convierte en guion y se antepone --ds-: --ds-feedback-warning-bg.
  • Los primitivos en CSS llevan --ds-p-<tema>-. Están prohibidos en componentes y productos; existen solo para que la capa semántica los referencie.
  • Los estados se nombran con sufijo: -hover, -active, -text, -bg, -border.

2. Los ocho temas

Ocho temas independientes; ninguno es la variante clara u oscura de otro. Cada uno redefine solo la capa semántica y cada uno deriva su propia rampa de neutros, mezclada en OKLab entre su color claro y su color oscuro. Por eso los grises de signal-blue tiran a azul marino y los de emerald-ink a verde tinta.

Colisiones de color resueltas

Dragonfruit: rosa de marca contra danger

  • Danger se desplazó del rojo-rosa al bermellón (#FF7A52): unos 38° de tono de distancia del rosa #FF4696 y más claridad cálida.

  • Todo error lleva el ícono ⊗ y un texto que dice qué pasó. El rosa nunca lleva íconos de estado.

El RFC no coincide con el del proveedor.

Butter Yellow: amarillo de marca contra warning

  • El amarillo es solo destaque: marcatextos de búsqueda, chips de novedad, banner de anuncio. Nunca comunica estado.
  • Warning pasó a ocre (#9A5600) sobre crema anaranjada (#FDEAD8), unos 40° de tono lejos del amarillo y mucho más oscuro.
  • Toda advertencia lleva el ícono △ y la palabra que la nombra. Las acciones usan Royal Iris, no amarillo.

// Recalcula el contraste WCAG 2.x leyendo las variables CSS ya resueltas.
function dsContrastAudit(theme, pairs) {
  const probe = document.createElement("div");
  probe.dataset.theme = theme; document.body.append(probe);
  const css = getComputedStyle(probe);
  const hex = v => { const h = css.getPropertyValue(v).trim().replace("#", "");
    return [0, 2, 4, 6].map(i => i < h.length ? parseInt(h.slice(i, i + 2), 16) / 255 : 1); };
  const over = (f, b) => f.slice(0, 3).map((c, i) => c * f[3] + b[i] * (1 - f[3]));
  const lin = c => c <= 0.04045 ? c / 12.92 : ((c + 0.055) / 1.055) ** 2.4;
  const L = ([r, g, b]) => 0.2126 * lin(r) + 0.7152 * lin(g) + 0.0722 * lin(b);
  const base = hex("--ds-surface-base");
  const rows = pairs.map(([fg, bg, min]) => {
    const B = over(hex(bg), base), F = over(hex(fg), B);
    const [a, b] = [L(F), L(B)].sort((x, y) => y - x);

  });

}

10. Patrones de IA

El módulo es transversal: se ve y se comporta igual en el ERP, la app móvil, la de inspección y la de RH. Su regla central: todo lo que generó un modelo vive en .ds-ai y lleva la etiqueta con el monograma y el nombre del asistente, por ejemplo «Sugerido por Atlas (IA)». La IA no tiene color propio: es neutra y se reconoce por su borde punteado, que significa «borrador hasta que una persona lo acepta». El punteado no se usa en ningún otro componente, y los tokens ai/* están reservados para este módulo.

Nombre del asistente

«Atlas» es un nombre provisional. Defínanlo una sola vez para todos los productos; el monograma es su inicial en ds-ai__mark. Siempre acompáñenlo de «(IA)».

En el ERP y en RH, prefiera la IA dentro del flujo (campos prellenados, resúmenes en paneles) antes que un panel de conversación. El chat es el patrón que más delata una interfaz genérica y el que menos ayuda en una captura.

La interfaz habla como un compañero de trabajo competente: claro, directo y respetuoso. Primero lo que importa; sin tecnicismos de sistemas.

12. Accesibilidad

WCAG 2.2 nivel AA es el piso en los cuatro productos. Lo que el sistema ya garantiza, y lo que cada producto debe cuidar:

Garantizado por la fundación

  • Contraste de texto ≥ 4.5:1 y de elementos no textuales ≥ 3:1 en los 8 temas (sección 3).
  • Foco visible con :focus-visible: anillo de 2 px en border/focus, separado 1–2 px, ≥ 3:1 en los 8 temas. Nunca se quita sin reemplazo.
  • Estados con ícono y texto además de color.
  • Objetivos táctiles ≥ 24 px (compact), 40 px (comfortable) y 56 px (field).
  • Movimiento reducido y modo de alto contraste de Windows (forced-colors).
  • Texto redimensionable al 200 %: todo en rem.

Responsabilidad de cada producto

  • <html lang="es-MX"> y un <title> por vista.
  • Un solo h1 por vista y jerarquía de encabezados sin saltos.
  • Puntos de referencia: header, nav, main, footer, y enlace «Saltar al contenido».
  • Orden de tabulación = orden visual. Sin tabindex positivo.
  • Textos alternativos en imágenes con información; alt="" en decorativas.
  • Tiempo suficiente: avisar antes de cerrar sesión y permitir extenderla.

Orden de tabulación

  1. Enlace «Saltar al contenido».
  2. Barra superior: menú, marca, búsqueda, notificaciones, cuenta.
  3. Navegación lateral.
  4. Contenido principal: migas de pan, título, acciones de vista, filtros, contenido.
  5. Dentro de un formulario: campos en orden de lectura; acciones al final (primaria al último).

Los componentes compuestos (pestañas, listbox, menú, tabla en modo cuadrícula, grupo de radios) son una sola parada de tabulación; dentro se navega con flechas.

13. Cómo se extiende por producto

Cada producto es un dialecto: hereda la fundación sin cambios y agrega solo lo propio. Un dialecto es un archivo <producto>.css cargado después de components.css, más su documentación.

Se hereda sin cambios
  • Los tres niveles de tokens y sus nombres.
  • Los 8 temas y sus valores semánticos.
  • Escalas de espaciado, tipografía, radios, elevación, movimiento.
  • Las 3 densidades y sus medidas.
  • Todos los componentes ds-* y su marcado.
  • El módulo de IA completo y sus tokens ai/*.
  • Redacción en español de México.
  • El piso de accesibilidad WCAG 2.2 AA.
Prohibido en un dialecto
  • Redefinir un token semántico o primitivo.
  • Usar colores, medidas o sombras literales.
  • Usar --ds-p-* directamente.
  • Usar ai/* fuera de contenido generado por IA.
  • Sobrescribir clases ds-* (en su lugar, cree clases nuevas con el prefijo del producto).
  • Bajar un contraste o quitar un foco.

Cómo agregar algo nuevo sin romper la fundación

  1. ¿Existe ya? Revise este documento. Si un componente ds-* resuelve el 80 %, úselo y documente la variante en el dialecto.
  2. Componente de producto: clase con el prefijo del dialecto (fld-scan), construida solo con tokens semánticos y de componente. Debe verse bien en los 8 temas y las 3 densidades, y pasar contraste.
  3. Falta un token: no lo invente en el producto. Agréguelo a tokens.json en los 8 temas, regenere themes.css, verifique contraste y suba la versión menor de la fundación.
  4. Un patrón se repite en 2 o más productos: se promueve a la fundación como ds-*.
  5. Cambio que rompe (renombrar o quitar un token o clase): versión mayor, con nota de migración y periodo en el que conviven el nombre viejo y el nuevo.
